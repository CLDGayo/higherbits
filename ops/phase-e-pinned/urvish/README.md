# 0xUrvish capture

`manifest.json` pins the 24 names shown on the 21st.dev creator profile to original files in `iurvish/uselayouts`. Source files and the root MIT license are copied from the Git commits recorded per item. `list-item` and `status-button` are historical entries absent from the current registry.

The local stage has a HigherBits-authored demo and a bundled preview for each item. The source closure includes upstream hooks and UI helpers at the same pinned revision. `discrete-tab` has a browser-checked preview, a self-contained, interactive GHL export, and ten saved Antigravity-guided prompts. Other items still need individual GHL and prompt review. Six source files reference remote images whose rights are not established by the repository's MIT license; their preview HTML and PNG files stay in `private-previews/`, outside the deployable web directory, and the publisher blocks them pending separate evidence. See `DEPENDENCY_LICENSE_REVIEW.md` for the exact MIT Hugeicons renderer/free-icon versions required by the other components.

Run `node ops/emit-pinned-urvish-production.mjs --check` for per-item readiness. `node ops/stage-pinned-urvish-agy.mjs --all` resumes local Antigravity guidance and GHL generation for items without remote references. A staged item can emit SQL only with `--emit-sql <slug> <review.json>` after the exact release commit, prompt hashes, and artifact hashes have been reviewed. The review must include `deployedAssets[slug].html` and `.png`, each with its deployed HTTPS `url` and local `sha256`; the emitter fetches both URLs and compares their bytes before using them. These assets are served from the VPS app's `apps/web/public/auto-index/` directory, synced by `sync-to-vps.sh`. Emission writes SQL to stdout; it does not connect to the database. Production publication and source-asset deployment are separate ordered actions.
